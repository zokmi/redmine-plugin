# MCP 本機端點掉線復原

2026-11-18 的初始檢查確認 127.0.0.1:18765 無監聽者，active.json 的 Node supervisor PID 已不存在。現有兩層服務只監督 Python/Node worker，無法恢復 supervisor。日誌未記錄最後退出原因，故中途斷線崩潰僅為待驗證風險。

調查期間另一個已部署 Python supervisor 開始監聽 18765，但 active.json 仍指向舊 PID。自動復原必須識別外部監聽，禁止自行停止或冒認其他部署。

新增 -Recover 模式以已安裝的穩定執行路徑和目前使用者排程工作定期確認。活服務以 PID、啟動時間、映像與監聽埠所有權判斷，避免每分鐘建立 MCP session。程序消失且埠空閒時重啟同一引擎；程序身分不符或外部埠占用時拒絕更動。首次安裝/明確重啟建立每分鐘與登入復原排程，保留 install.lock。排程引數及 manifest 不含明文權杖或 API 金鑰，沿用使用者權杖及可驗證的設定路徑。環境不相容時明確拒絕。

Python proxy 補入 incoming abort/error 的上游清理與回應串流錯誤處理。驗證以隔離安裝、測試權杖、測試埠進行，涵蓋 supervisor 終止後恢復、活服務重複檢查、外部監聽、PID 重用和中途上傳斷線。實際排程安裝前以臨時名稱實測並清理，實際部署先驗證身分和現況。
