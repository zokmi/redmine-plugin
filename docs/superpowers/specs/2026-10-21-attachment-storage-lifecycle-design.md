# 附件自動目錄與暫存壓縮清理設計

日期：2026-10-21
狀態：對話設計已確認，書面規格待使用者審閱。

## 目的與已確認範圍

移除附件上傳及下載位置的手動參數設定，讓對話中取得且 MCP 執行環境可存取的附件可直接上傳，下載則自動存入使用者應用程式資料目錄。使用者不必搬檔或設定來源目錄。

只管理套件建立的本機暫存：閒置滿 7 天後壓縮，壓縮完成後保留 30 天再刪除。使用者原始檔、既有自訂目錄與 Redmine 伺服器附件均不納入清理。期限固定，不新增管理參數。

## 現況與影響範圍

目前 config.py 解析 download_dir、upload_dir 與相關環境變數，upload_dir 未設定時沿用 download_dir；目錄缺漏會停用附件功能，包括 base64 上傳。tools/attachments.py 限制上傳來源在允許目錄內，下載按站台建立子目錄。config_file.py、setup 精靈、設定編輯命令、範例與文件也公開這兩個設定。

變更涵蓋上述設定與附件流程，以及 server 啟動時的清理整合。保留既有大小上限、站台解析、下載同源驗證、檔名淨化與圖片格式驗證。upload token 仍須透過既有寫入工具掛到 issue，此生命週期不變。

## 自動目錄

新增獨立附件儲存模組，負責目錄解析、管理紀錄、檔案使用鎖、封存與清理。附件工具只透過該模組取得或使用管理路徑。

- Windows：%LOCALAPPDATA%/redmine-mcp/attachments；變數缺漏時用使用者家目錄下 AppData/Local。
- macOS：~/Library/Application Support/redmine-mcp/attachments。
- Linux：$XDG_DATA_HOME/redmine-mcp/attachments；未設定或非絕對路徑時用 ~/.local/share/redmine-mcp/attachments。

站台儲存鍵由正規化的站台 URL 產生穩定雜湊；不同 URL 即使站台代號相同仍隔離，代號更名不改變既有歸屬。API key 不進入路徑或管理紀錄。每站下分 active、archives 及管理紀錄。每次下載建立唯一項目目錄，避免同名、同 id 與並行操作互相覆蓋。

自動目錄只按需建立；不可寫入時附件操作回報明確錯誤，不退回工作目錄或使用者任意目錄。清理初始化失敗只記錄警告，不影響 server 其他工具。

## 上傳與下載

upload_attachment 保留 file_path、content_base64、filename、site 的介面。file_path 接受執行環境可讀的本機一般檔案，移除 upload_dir 限制；不解讀 URL、不搜尋磁碟、不掃描對話歷史，也不取得宿主未暴露的附件。工具描述須指示呼叫端直接使用對話附件提供的實際路徑；路徑不可存取時回報錯誤，不假裝上傳成功。

外部來源直接讀取，不為封存而額外複製，絕不移動、修改或刪除原件。來源須排除目錄、裝置、管線與符號連結／Windows reparse point；由實際讀取資料限制大小，避免僅以讀取前 stat 作為上限保證。base64 上傳不再依目錄設定停用，沿用現有圖片驗證，不必落地。

若上傳來源屬本模組管理的有效暫存，操作期間取得使用鎖並更新最後使用時間；外部來源不登記為可清理項目。直接指定路徑擴大了工具可讀來源，文件須明確交代此行為，但不新增人工搬檔或逐檔確認流程。

下載先寫唯一暫存檔，成功後原子發布完整檔案與管理紀錄，再回傳實際 path；失敗不回傳完成路徑。既有回傳欄位維持相容。管理紀錄失敗時保留檔案並警告，該檔不得僅因位於目錄內而被清理。

## 閒置與壓縮政策

閒置時間以套件記錄的最後使用 UTC 時間為準；首次下載完成即建立時間，透過套件再次讀取上傳時刷新。外部程式直接開檔不屬可觀察活動，文件應說明回傳路徑是有保留期限的暫存，需永久保存時自行複製。

最後使用時間距現在大於等於 7 × 24 小時且未被使用時，按項目壓縮成 ZIP。先在同一管理目錄建立臨時壓縮檔，再完整驗證 ZIP CRC、項目大小及內容 SHA-256；驗證成功後原子發布壓縮檔並持久保存封存完成時間，最後才刪除該管理項目的暫存原件。壓縮失敗、內容變動、鎖衝突或紀錄寫入失敗均保留原件，待下次重試。

封存完成後不因每次掃描延長期限；封存完成滿 30 × 24 小時才刪除已登記的壓縮檔。時間在未來的紀錄跳過並警告。封存不提供自動解壓工具，使用者可直接解開 ZIP；下載路徑在封存後不再承諾有效，可重新下載 Redmine 附件。

## 清理觸發、並行與復原

server 啟動後啟動非阻塞清理，每次附件操作完成並釋放檔案後也嘗試觸發。行程內最多每小時掃描一次，啟動掃描例外；沒有常駐行程或操作時不承諾準點清理，不新增排程器。

掃描與壓縮放入背景工作，避免阻塞事件迴圈或 MCP 啟動。跨行程以作業系統釋放即解鎖的檔案鎖協調；取得不了即跳過，禁止僅以鎖檔存在或時間判斷使用狀態。上傳讀取與清理同一管理項目互斥，掃描器也互斥。停止行程不必等待所有項目壓縮完成。

以明確狀態紀錄區分 active、封存已發布、原件已移除；中斷重跑時驗證已發布檔案再繼續，不能把半成品當成封存成功。無管理紀錄、紀錄損壞、歸屬不明或路徑不符的檔案一律保留並警告。清理只處理模組登記且路徑仍位於管理根內的項目；不跟隨符號連結、junction 或其他 reparse point，不遞迴刪除整個目錄。

警告送 stderr 日誌，不寫 stdout、不包含憑證或檔案內容。壓縮與清理失敗不使已完成的附件操作失敗。

## 舊設定相容與文件

舊 TOML 全域及站台的 download_dir、upload_dir 仍接受但忽略，啟動時給一次棄用提示。REDMINE_DOWNLOAD_DIR、REDMINE_UPLOAD_DIR 同樣忽略並提示。缺省路徑不再停用附件，須在升級說明指出此行為變更。

設定精靈、範例、help 與可編輯設定鍵移除路徑選項；顯式嘗試用設定命令寫入舊鍵時回報已改自動管理。讀取或一般設定更新不主動改寫使用者舊設定檔，也不建立、搬移、壓縮或清理其舊路徑。max_attachment_mb 保留。

README、SETUP、config.example.toml 與附件相關 skill 說明須同步自動位置、對話附件直接上傳、暫存期限、重新下載方式及舊設定相容行為。不得宣稱所有聊天平台附件均可直接存取。

## 驗證與驗收

以可注入時間與暫存管理根測試，避免等待真實期限或清理使用者資料：

1. Windows、macOS、Linux 路徑與缺省／非絕對 XDG 回退；不依目前工作目錄。
2. 全新設定無路徑仍可下載、file_path 與 base64 上傳；舊設定被忽略且舊目錄不變；精靈不再詢問目錄。
3. 管理目錄外的一般附件可直接上傳，原件內容、位置不變；不存在、不可讀、非一般檔案、連結及超限來源明確失敗。
4. 不同站台 URL、相同附件 id／檔名、並行下載隔離；保留既有下載同源與檔名防護測試。
5. 7 天與封存後 30 天的前一刻、恰好到期及逾期；刷新使用時間、未來時間及重啟不延長封存期限。
6. 內容驗證成功才移除原件；壓縮失敗、磁碟滿、權限錯誤、來源變動、紀錄損壞與各階段中斷重跑仍保留可恢復資料。
7. 多行程掃描、使用中上傳與清理競爭、鎖自動釋放；連結目錄及管理根外誘導路徑不被清理。
8. 使用者原件、舊自訂目錄、未登記檔案與 Redmine 遠端附件不變；只刪除已到期且驗明歸屬的封存項目。
9. 啟動與附件工具在清理失敗時可用，stdio 不受日誌破壞；執行既有附件、設定、精靈及 server 回歸測試與專案 lint／型別檢查。
