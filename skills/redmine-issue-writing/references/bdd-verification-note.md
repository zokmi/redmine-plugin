# BDD 驗證後續註記

更新前必須先取得一致性審核子代理的 `PASS`。審核代理應使用當下動態選出的適用 skill，讀取 issue 完整需求、git 變更與 BDD 證據；不得修改檔案或寫入 Redmine。

只有審核通過、BDD 全部通過、截圖已遮罩且附件／註記儲存結果已確認，才能追加以下格式：

```markdown
## 修正與驗證結果

### 修正項目 1：<修正項目名稱>

- 問題／需求：<對應 issue 條目>
- 根因：<已確認根因；未知時寫未確認>
- 修正內容：<實際修改>
- 一致性審核：與 issue 要求一致
- 驗證結果：通過
- 驗證情境：<Scenario 名稱與編號>
- 驗證版本：<受測 commit SHA>

圖片 1：<已上傳附件名稱或連結>

### 修正項目 2：<修正項目名稱>

- 問題／需求：<對應 issue 條目>
- 根因：<已確認根因；未知時寫未確認>
- 修正內容：<實際修改>
- 一致性審核：與 issue 要求一致
- 驗證結果：通過
- 驗證情境：<Scenario 名稱與編號>
- 驗證版本：<受測 commit SHA>

圖片 2：<已上傳附件名稱或連結>
```

每個修正項目都要有同編號的圖片。若是純 API／DB 情境，不能捏造圖片，改寫成：

```markdown
圖片 1：截圖不適用；請求／回應或查詢證據：<報告路徑、附件或可重現指令>
```

附件上傳或註記儲存未確認時，回報部分完成並停止後續結案，不得宣稱 Redmine 已更新完成。
