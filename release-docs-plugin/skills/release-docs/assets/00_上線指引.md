## 備份與唯讀 preflight

確認目標 server/database、正式 DB provider 與版本、執行權限、維護窗口、應用程式停寫需求及舊版 baseline 相符。逐一確認 table、column、index、FK、constraint 與 extended property 的完整定義及資料前置條件，不能只確認物件名稱。

上線前完成備份或快照，確認備份可還原、保存位置與負責人；未完成備份或 preflight 即停止。確認本次排除物件維持既有狀態。結構異動說明或範圍待確認時，先補齊並重新審查。

## 完整驗證與部署

`01_部署SQL.sql` 是唯一人工 SQL 入口；不拆開執行 SCHEMA、REPAIR、DATA、VALIDATION。交付檔目前設定 {{MODE}}，每次執行前確認模式，模式調整需保存對應審查與執行證據。

1. 在隔離 disposable database 從舊版結構建立 fresh baseline，載入隔離 fixture。以單一 connection/session 完整執行 `01_部署SQL.sql`，設定 ValidateOnly=1；全部驗證成功後 ROLLBACK。確認沒有持久化 schema/data 異動、沒有未提交 transaction。
2. 關閉第一次連線，另建 fresh baseline，以新 connection/session 設定 ValidateOnly=0 重新完整執行相同 SQL；全部驗證成功後 COMMIT。第二次不可接續第一次 connection 或 transaction。
3. 在已 commit 的隔離資料庫重跑，確認欄位、index、constraint 與資料不重複且結果收斂。另從 fresh baseline 注入預期錯誤，確認 rollback、THROW、錯誤定位及後續 unit 未執行。
4. 正式環境完成備份與 preflight 後，使用新 connection/session 與 ValidateOnly=0 完整執行；保存 execution evidence，執行部署後查核。

## 失敗立即停止

任一錯誤必須 ROLLBACK、THROW 並停止後續 unit；不跳過失敗 unit，不將 RAISERROR 或工具 exit code 當成唯一停止判據。禁止在未知 transaction 狀態續跑。先確認 transaction action 與 rollback 結果，再修正可追溯來源、重新產製及審查後從 fresh baseline 驗證。

GO、ALTER DATABASE、WITH ROLLBACK IMMEDIATE 與不可交易 DDL 若未有受控執行策略與審查證據即停止；不能宣稱外層 transaction 能還原這些操作。

## 結構化錯誤回報

保留 SQL Server 原始 THROW 與下列回報欄位：

| 欄位 | 定位與處置用途 |
| --- | --- |
| ReleaseId、DatabaseName、ServerName、ValidateOnly | release、資料庫、伺服器與執行模式 |
| Phase、UnitId | SCHEMA／REPAIR／DATA／VALIDATION 與失敗單位 |
| SourcePath、SourceRevision、SourceLine、artifact 行號 | 原始來源及交付 SQL 定位 |
| ErrorNumber、ErrorSeverity、ErrorState、ErrorProcedure、ErrorLine、ErrorMessage | SQL Server ERROR_* 錯誤資訊 |
| XactState、TranCount、TransactionAction | XACT_STATE()、@@TRANCOUNT、ROLLBACK 或 COMMIT 未執行 |
| 停止原因、建議處理動作 | 確認回復結果、修正來源與重新驗證 |

錯誤回報與執行紀錄須遮罩密碼、token、連線字串；禁止直接張貼機密原值。只有 exit code 或「執行失敗」不足以完成回報。

## 部署後查核

查核受影響 table/column 完整定義、index 定義、FK/constraint trust、extended property、資料筆數與保留資料、應用程式功能、排除物件未受異動，以及沒有遺留 transaction。核對所有 unit 結果；保存 server/database、執行模式、工具版本、時間與查核證據。若有 `02_參數異動.md`，依該文件套用、重新載入並驗證服務。
